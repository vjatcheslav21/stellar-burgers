
# Проект «Stellar Burger» (Redux-хранилище)

## Описание проекта

Stellar Burger — это полноценное _SPA (Single Page Application)_ для заказа космических бургеров. Проект представляет собой комплексную работу с архитектурой **React-приложения**, использующим **Redux** для управления глобальным состоянием.

Основная задача заключалась в интеграции маршрутизации, работы с асинхронными запросами к **API** и реализации механизма авторизации с защитой приватных данных пользователя.

## Используемые технологии

- **React:** Функциональные компоненты и хуки.
- **Redux Toolkit:** Создание стора, слайсов _(createSlice)_ и асинхронных экшенов _(createAsyncThunk)_.
- **React Router DOM (v6):** Настройка маршрутизации, работа с вложенными и динамическими маршрутами, редиректы.
- **TypeScript:** Строгая типизация данных и компонентов (использование .tsx).
- **API:** Асинхронные запросы к серверу для получения ингредиентов, заказов и управления профилем.

  ## Функциональные возможности

### 1. Маршрутизация и навигация

Реализована навигация по всем основным разделам приложения с контролем доступа:

- **Публичные маршруты:** Конструктор бургеров _(/)_, Лента заказов _(/feed)_, страница _ingredient (/ingredients/:id)_.
- **Защищённые маршруты:** Профиль _(/profile)_, История заказов _(/profile/orders)_, сброс пароля _(/reset-password)_. Доступны только авторизованным пользователям.
- **Модальные окна:** Реализован переход к модальным окнам через динамические маршруты (например, /feed/:number для деталей заказа), что позволяет открывать их по прямой ссылке и корректно работать с кнопкой "Назад" в браузере.
  Активное состояние ссылок в шапке определяется текущим маршрутом, включая вложенные пути.

### 2. Управление состоянием (Redux)

- **Архитектура:** Данные разделены по слайсам (ингредиенты, пользователь, заказы).
- **Асинхронность:** Использование Thunk для запросов данных с сервера. Реализованы состояния загрузки _(loading)_, успешного завершения _(fulfilled)_ и ошибок _(rejected)_ для UX (индикация загрузки).
- **Селекторы:** Для получения данных из стора в компонентах используются оптимизированные селекторы.

### 3. Авторизация и профиль пользователя

- **Реализован полный цикл аутентификации:** Регистрация, Вход, Восстановление пароля и Сброс пароля.
- **Редактирование профиля:** На странице профиля данные подставляются из стора.
- **Реализована логика кнопок:**
  При изменении данных появляются кнопки «Отмена» и «Сохранить».
  «Сохранить» отправляет обновленные данные на сервер.
  «Отмена» откатывает изменения к исходному состоянию.
- **Защита роутов:** Попытка перейти к заказу или в личный кабинет без авторизации перенаправляет пользователя на страницу логина.

### 4. Лента заказов и история

- **Лента заказов (/feed):** Доступна всем. Обновляется в реальном времени при создании новых заказов. Производит подсчёт стоимости каждого заказа на основе его ингредиентов. Отображает общее количество заказов и заказов за сегодня.
- **История заказов (/profile/orders):** Доступна только авторизованным пользователям. Отображает личную историю со статусами («Готовится», «Выполнен», «Отменён»).
- **Детализация заказа:** При клике на заказ открывается модальное окно с подробной информацией. Работает корректная навигация и для общей ленты, и для личного кабинета.

### 5. Конструктор бургеров

- Возможность заказа доступна только авторизованным пользователям.
- Интеграция с API для отправки собранного бургера на сервер.

### Реализация (Workflow)

Работа над проектом велась в два этапа для оптимизации процесса:

- **Каркас приложения:** Сначала была настроена структура роутинга и созданы компоненты страниц-заглушек.
- **Логика и данные:** Далее разработана _Redux-логика (слайсы, thunk)_, подключены данные из API и внедрены в UI-компоненты.
